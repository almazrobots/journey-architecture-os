# Example — B2B SaaS customer onboarding

> Fictional example. Not research evidence.

## Journey header

- ID: `JRN-CUST-SAAS-ONBOARD-001`
- Actor: new admin at a small B2B customer
- Trigger: contract is signed and admin account is created
- Desired outcome: team reaches first useful workflow with confidence
- State: hypothesis current state

| Stage | Goal | Actions | Friction | Evidence status | Outcome |
|---|---|---|---|---|---|
| Gain access | Enter product | Find invite, set credentials | Invite may be missed | hypothesis | Account accessible |
| Understand setup | Know what must be configured | Read guide, explore | Terminology unclear | hypothesis | Setup plan understood |
| Configure | Make product fit team | Add users, permissions, settings | Unclear minimum configuration | hypothesis | Viable configuration |
| First workflow | Produce first value | Run core workflow | Errors have weak recovery | hypothesis | First useful result |
| Expand | Bring team into routine | Invite colleagues, repeat | Value may not be visible to others | hypothesis | Repeatable team use |

## Research questions

- What do successful admins do in the first 48 hours?
- Which configuration steps correlate with first value?
- Where do customers leave the product and seek external help?
- What does "first useful result" mean by customer segment?

## Why this example is intentionally incomplete

A real current-state map should not invent emotion, frequency, or root causes without evidence.
